# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Code Alexa is a local-first whiteboard workspace, in the style of Heptabase, built with Tauri 2, React 19 and Rust. The sibling `../weave` folder is an earlier frontend-only prototype. It is reference material, not part of this app.

## Commands

```bash
npm test                                                  # frontend unit tests (node:test)
node --test --test-name-pattern="吸附" tests/snap.test.ts  # one file, filtered by test name
npx tsc --noEmit                                          # typecheck src/ (tests/ is not covered)
cargo test --manifest-path src-tauri/Cargo.toml           # all Rust tests
cargo test --manifest-path src-tauri/Cargo.toml compaction  # Rust tests matching a name
npm run tauri dev                                         # run the full app
npm run tauri build                                       # release bundle
```

There is no linter config. `npm test` runs TypeScript directly through Node's type stripping, so code imported by tests needs `.ts` import extensions and erasable-only syntax (no `enum`).

## Architecture

**Rule from the owner: TypeScript is frontend only. All backend logic lives in Rust**, including the data model, CRDT, ordering and SQLite. Do not move data rules into TypeScript. Treat the Markdown parser as display: for non-card notes Rust stores the Markdown string unchanged, and for cards `model/card_markdown.rs` generates it from blocks.

### Backend (`src-tauri/src`)

- `commands.rs` is a thin adapter around a `Mutex<Alexa>`; rules live in `model/`. A new command must be registered in `lib.rs`, wrapped in `src/api.ts`, and any changed payload mirrored between `model/types.rs` and `src/types.ts`.
- `model/` holds `impl Alexa` split across domain modules. Each of these is its own Yjs document (`yrs`): the workspace directory, every whiteboard, and every note. They load lazily.
- `persisted.rs` wraps a `Doc` with its SQLite log: updates are appended to `doc_update` and compacted into `doc.snapshot` after 500 updates. A failed write stays in memory and is retried on the next save.
- `media.rs` keeps images and videos in `<data dir>/media/<aa>/<sha256>.<ext>`, outside SQLite, and serves them through the `media://` protocol with Range support. Files are immutable. Notes record the file name in `context.media`, and `delete_notes` returns files no note uses any more. `MediaStore` does not touch `Alexa`, so file I/O never holds the global lock.
- `drawio.rs` serves the bundled editor (`resources/drawio`, trimmed from the official `draw.war`) through the `drawio://` protocol. **Tauri injects IPC into iframes on Windows and treats them as local, so both protections there are required:** the origin check in `invoke_handler` in `lib.rs`, and the CSP on every Draw.io response. Neither alone is enough. XML lives in `context.xml` as one last-writer-wins value, never in `Y.Text`. The preview is a media file.
- `model/office.rs` is shared by Writer, Excels (`sheet`) and Slides. `office_edit` wraps a change in one transaction, and each note has one in-memory `UndoManager`. Only continuous typing merges into one undo step; every other edit calls `split_undo_step` on both sides. For these types `content` is not the source of truth: it is a plain-text summary rebuilt after each edit and undo, for the Library.
- `office_documents` nests charts under their source Excels. Ownership is derived on read from `context.source`, never stored, so a chart whose Excels was deleted returns to the top level. Older data may hold an unused `chartFolders` map and `context.folder`, left by a removed manual-folder feature.
- `model/writer.rs` stores blocks in the note doc's `blocks` map, with inline Markdown in a `Y.Text`. `model/sheet.rs` keeps tabs, tables, rows, columns, cells and objects in separate maps, and cells are keyed `rowId:colId`. **Formulas are stored with row and column ids, not coordinates** (`model/formula.rs`, hand-written), and are shown as A1 references on read, so inserting or deleting rows and CRDT merges cannot point them at the wrong cell. `CellRange` lists every row and column id it selected, so embedded cells and charts survive partial deletion. Results are calculated on read and never stored. `model/chart.rs` keeps only `kind`, `seriesBy` and `source` in `context` and reads its data from the sheet each time. `model/slides.rs` uses a fixed 1280×720 stage that must match `components/slides/stage.ts`.
- Fetch every root type (`get_or_insert_map`, `get_or_insert_text`) before opening a transaction on that doc. It needs the write lock, so calling it with a transaction open deadlocks and freezes the whole app behind the `Mutex<Alexa>`.
- `data_location.rs` lets the user choose the data folder. The choice is in `<base>/data-location.json`, because the database cannot record its own location; `<base>` is the app data folder, or `ALEXA_DATA_DIR` in debug builds, which stays the test isolation boundary. A move only copies: media without the lock, then under the `Alexa` lock a second media pass and `VACUUM INTO`, held until `app.restart()` so no edit lands after the copy. It never overwrites: a folder that already has `alexa.db` is switched to after validation. If the chosen folder cannot be opened at startup, the app uses `<base>` and reports `unavailable`; it must not create an empty database there.
- `storage.rs` never parses CRDT content. `doc` and `doc_update` are the source of truth. `note_index`, `note_references` and `search_fts` are rebuildable indexes and are currently unused; `sync_state` is reserved for future remote sync.
- Schema changes are appended to the `MIGRATIONS` array, tracked by `PRAGMA user_version`.
- Stored data must stay readable as Yjs documents (`reads_documents_written_by_yjs` checks this). `order.rs` matches the `fractional-indexing` package format for the same reason.
- Rust tests live in `model/tests/` and use an in-memory database; `reopen()` simulates an app restart.

### Domain model

The agreed conceptual model is `docs/er-diagram.drawio.svg`. It predates `arrows` and whiteboard nesting.

- A **card** is edited with the Writer block editor (`WriterEditor` with `card`), everywhere: fullscreen, right panel and in place on a whiteboard (`placement`). Blocks in the note doc are the source of truth; `content` is full Markdown rebuilt from them after every edit and undo by `model/card_markdown.rs`, so canvas painting, the Library, search and `mentions` keep reading `content`. A card with no blocks is imported from `content` on first read, which changes neither `content` nor `updatedAt` and is not undoable. `update_note_content` on a card clears the blocks so they rebuild from the new text. `card_markdown.rs` must stay in step with `markdown/parse.ts`: `- [ ]`, `- ▾`/`- ▸` (toggle), `> 💡 ` (callout), pipe tables and `![](media:<file>?w=&h=&p=)` for images. Cards have no paper, title, columns, alignment, page break, TOC, embedded cells or charts.
- A **Note** lives in the Note Library. A **Placed Note** is one appearance of a note on a whiteboard, so one card can appear on many boards, but at most once on each board (`place_note` enforces this). A sheet is the exception: a placement stores `tableID`, and each table can appear once per board (`place_table`). A placement without `tableID` shows the first table.
- Note types are `card`, `sheet`, `mindmap`, `mermaid`, `image`, `video`, `drawio`, `code`, `writer`, `slides` and `chart`. `content` is a Markdown string for cards, and `context` holds type-specific settings. Links and the `[[` picker use `card_library` (cards only). Card Library uses `card_notes` and Office Library uses `office_documents`, so Writer, Excels, Slides and charts never appear in Card Library; pickers that embed content use `note_library` (every type). On a whiteboard the right panel has both as tabs (`LibraryShelf`), which is how Office content reaches the canvas.
- **Writer, Slides and Excels are card surfaces.** While one is fullscreen it hands App a `CardSurface` (`cards/cardSurface.ts`) and the right panel shows Card Library, cards only, dragging onto the document instead of the board. A placement stores only the note id: a Writer `card` block, a Slides `card` element, or an Excels object (`noteType` is derived on read, so charts and cards share `objects`). `PlacedCard` reads the note on `cardRevision`, so the same card follows every edit; double-click opens it in the right panel and the document stays open. Rust enforces what `place_note` does: once per document, per slide and per sheet tab (`check_placeable` also rejects Office types, and cards cannot hold cards), and duplicating a block or element skips cards. Placements appear in backlinks through `office_targets`. Deleting a card leaves a message in Writer and Slides, and drops the object in Excels.
- **Root** is a fixed board (`id = root`) that holds only whiteboards. Whiteboards nest through `parentId`. A whiteboard tile uses the whiteboard id as both placement id and `noteID`, and has no note doc.
- **Tags** are workspace-wide (`model/tags.rs`). Names and colours live only in the workspace doc's `tags` map; a note doc stores tag ids in its own `tags` map, and `read_note` resolves them into `Note.tags`, so rename and recolour write one place and every payload, including `BoardState`, already carries them. Deleting a tag only changes the directory: leftover ids are skipped on read. The note `tags` map is outside every undo scope and does not touch `updatedAt`, so tagging never reorders a Library. `add_note_tag` reuses an existing name, ignoring case. Whiteboards have no tags. Colour names in `TAG_COLORS` must match `components/tags/tagColors.ts`, which owns the actual colours. `TagBar` sits above the content in the right panel and fullscreen; `useTagFilter` follows `useTypeFilter` in every Library (several tags mean all of them); `TagLibrary` manages tags and lists every note type; the canvas paints colour bars in the card header strip (`drawTagBars`).
- **Links are derived, never stored.** Card links are Markdown `[text](note:<noteId>)` and arrows live in the board doc's `arrows` map, attached to placements. `model/links.rs` computes Note References on read, because a stored copy could drift from CRDT merges. Before indexing into the `note_references` table, reconcile its `source` check (`manual`/`inline`) with the derived values (`mention`/`arrow`).

### Frontend (`src`)

- `components/tabs/` is the tab bar of the workspace area. The side panels are not tabbed: selection and the right panel are global, and a tab only records `page`, `whiteboardID` and `fullscreenID`. `tabs.ts` is pure and unit-tested; the state lives in `App` and is kept per device in localStorage, like panel widths, and `restoreTabs` drops deleted boards and notes. Only the active tab is mounted, so a switch goes through `changeTabs`, which waits for `CardFullscreen.flush` (Draw.io cannot export once its iframe is gone) and for `select_whiteboard` before changing state. `.tab-content` is the positioned parent that `.card-fullscreen` fills, so fullscreen never covers the tab bar. The right panel returns to Library in `openWhiteboard`, not on canvas mount, because a tab switch remounts the canvas too. Dragging a tab listens on `window`: reordering moves DOM nodes, which drops pointer capture.
- `api.ts` is the only path to Rust. Its queue sends every command in order so stale writes cannot overwrite newer ones.
- `components/canvas/` is imperative HTML canvas, not React. `controller.ts` (`BoardController`, one per board) owns state and events, and `scene.ts` draws. React renders only the overlays: inline inputs and menus. Geometry helpers (`snap`, `resize`, `viewport`, `arrow`, `gestures`) are pure and unit-tested.
- `components/canvas/notePreview.ts` caches the image each non-card type paints on the canvas. Register a type in `PREVIEW_RENDERERS` in `controller.ts`. `components/mermaid/` renders diagrams; `note.content` holds the Mermaid source and Rust never parses it. `MermaidEditor` is the IDE: `code/CodeArea.tsx` (line numbers, error line), `templates.ts` and `DiagramView.tsx` (wheel zoom, drag pan). When upgrading Mermaid, check that every entry in `TEMPLATES` still renders, because their tests do not render them.
- Video width, height, duration and poster are unknown to Rust: `components/media/videoProbe.ts` decodes them after import and `save_video_info` stores them. Canvas shows the poster; `VideoPlayer.tsx` is a single overlay positioned by `updateVideoAnchor`. `import_media_files` bypasses the `api.ts` queue on purpose, because copying a large video must not block edits.
- `components/code/` is the Code Block type. `note.content` holds the source and `context.language` the language (absent means plain text); Rust parses neither. `highlight.ts` and `grammars.ts` are a hand-written tokenizer whose output must always join back to the input. Cards are painted as vector text, not through `PREVIEW_RENDERERS`, and fit their content like Markdown cards. `CodeArea.tsx` is the shared editing surface; edits go through `execCommand` so native undo keeps working. To add a language, add it to `grammars.ts` and `languages.ts`. Markdown code blocks use the same tokenizer: the language lives in the fence, so Rust is not involved, and the editor's toolbar shows `LanguageSelect` while the caret is in a block. Highlight spans are real DOM, so a keystroke that changes the tokens rebuilds the editor content and restores the caret.
- `components/mindmap/` is the mind map UI, modelled on Miro: root in the centre, branches on both sides, coloured lines, `+` buttons and a toolbar above the selection. Each first-level branch stores its `side` and `color`; deeper nodes inherit the colour, and the root stores the map's `orientation` and `lineStyle`. On a whiteboard `MindmapEditor` opens in place (`inline` prop) as an overlay on the card: pan and zoom belong to the board, the root stays fixed, and the card resizes to wrap the map through `fitMapCard`. Clicks on the card find the node with `nodeAtCardPoint`, so a click on a node opens the editor on it. Mermaid and mind map cards have no card background on the canvas. Rust (`model/mindmap.rs`) owns the tree: nodes live in the note doc's `mindNodes` map, and reads repair cycles and orphans from CRDT merges by attaching them to the root. `content` mirrors the root text as the title. Its order keys come from `key_between`, which must not be mixed with `key_after` keys. Changes reach the canvas through `noteChanged` in `App.tsx`, because they are not in `content`.
- `components/office/` holds what Writer, Excels, Slides and charts share: `OfficeLibrary` (the Left Panel page, with Card Library's operations plus the new-document buttons), `OfficeSummary`, `DocumentTitle`, the range and note pickers, `CellsView` for embedded cells, `SheetItems` (the tables and charts inside an Excels tile, shared by the Library and the whiteboard panel), `useEditorHistory` (Ctrl+Z and Ctrl+Y go to Rust), `TablePicker` (which table a sheet card shows) and `officePreview.ts` (canvas previews, registered in `PREVIEW_RENDERERS`; sheet previews are cached per table through the `variant` of `NotePreviews.get`).
- `components/writer/` is the Notion-style block editor. Each block is a `contenteditable` that reuses the Markdown inline parser; `rules.ts` is the pure logic. The DOM is the truth while typing, and only structural edits re-render from Rust. Blocks must register in a layout effect, because the parent places the caret in its own layout effect right after a block is created.
- Writer is laid out on paper like Word. Rust stores the paper name, orientation and margin name in the note doc's `page` map (undoable); `pageFormat.ts` turns them into pixels, and its name lists must match `model/writer.rs`. `paginate.ts` is pure, and `usePagination.ts` applies it after clearing all breaks. Whole blocks move with `--writer-break`. A paragraph splits between lines through a floated `::before` with `shape-outside` on `.writer-text`, so the text DOM, caret and IME are untouched. Measure after every band, never predict: browser rounding accumulates and hides the last line under `.writer-break`. A blank line has zero width and cannot be pushed by a band, so `paginate` handles each line once or it never terminates. `PageSetup` is a popup whose button is portalled into the fullscreen title row through `toolsSlot`, and its Esc must not reach `CardFullscreen`. The right panel passes `draft` and shows no paper, because a page scaled to that width is unreadable.
- Writer headers and footers live in the same `page` map: three plain-text slots each, plus `number` (place, align, format) and `skipFirst`. The number itself is never stored; `pageFormat.ts` builds it from the page count. `PageBands` positions them absolutely in the margins, above `.writer-break`, so they never enter pagination, and a double-click swaps that page's band for inputs. Typing updates `page` state at once, so other pages follow live, and saves through `flush` with `typing: true`, which merges undo steps. `box` is memoised on size, orientation and margin so this does not repaginate. `set_writer_page` writes only changed keys, because typing saves repeatedly.
- Writer document features: `pagebreak` is a block; `paginate` leaves the marker where it is and starts the next block on a later page, tracked per flow so a break inside a column affects only that column. Block `align` and image `width` (percent of the available width) are fields on the block. `WriterFind` searches the rendered text and marks it with the CSS Custom Highlight API, so the DOM is not touched, and replaces through `execCommand` so the normal input path saves it. `refreshContent` reads word count and `toc` entries from the DOM, because that is the truth while typing. The TOC walks `.writer-row` headings in the DOM, so an embedded Note's headings join it in reading order; `EmbeddedNote` reports `onContentChange` so edits there refresh it. Printing sets `printing`, which reruns pagination on `printBox` (no gap between sheets, scale 1) before `window.print()`; the `@media print` rules at the end of `App.css` hide everything but `.writer-page`, keeping its ancestors through `:has`.
- A Writer `table` block stores `string[][]` as one JSON last-writer-wins value (`table`), not Yjs cells, and `table.ts` holds its pure logic. Rows are `.writer-table-row` divs, not `<tr>`, so pagination can push one row to the next page. Clipboard tables are checked before images, because Excel also puts a picture of the table on the clipboard. Columns (up to `MAX_COLUMNS`, in both `model/writer.rs` and `rules.ts`) are flat blocks sharing `group` with a `column` number, in reading order, and are only created by dragging a block beside another (`moveBeside`). `blockRuns` wraps them, each column paginates on its own, and `tidy_columns` closes numbering gaps and clears a group left with one column on read. Break variables differ per level (`--writer-break`, `--writer-group-break`, `--writer-row-break`) because custom properties inherit. A pasted image is an image note with no placement (`import_writer_image`).
- A Writer `card` block shows a Library note through `PlacedCard` as part of the text flow, with no card frame. A Note is edited in place: `renderNote` mounts a nested `WriterEditor` (`card embedded`) with no handles, its menus portalled to `body` because the page uses `zoom`, and it reloads on `revisionFromOutside` only while unfocused. Pagination treats each nested `.writer-row` like a table row (`tableRowsOf`). A Note placed in the open document shows as edited elsewhere in the right panel. Other note types stay read-only. In Slides and Excels a double-click on a Note mounts the same `EmbeddedNote` in place; `onClose` makes it close on an outside click or Esc, and while it is open pointer events must not start a move and keys must not reach the stage. Writer is the only surface with `office`: its right panel has the Office Library tab, a dragged table becomes a `cells` block over all its current rows and columns, and a chart becomes a `chart` block.
- A Writer `cells` block is `LinkedTable`: it reads the range on each revision, and a commit writes `setCells` to the sheet, so Writer holds no copy. Focus shows the raw formula and blur commits. Ctrl+Z in a linked cell goes to the sheet's history, not the Writer's. It shares `.writer-table-row` with native tables so pagination treats both alike. `CellsView` stays read-only for Slides. Copying from Excels puts the `CellRange` in a `data-alexa-cells` attribute on the clipboard HTML (`office/cellClipboard.ts`), and Writer's paste checks that first; one cell pastes as text. `columnTemplate` gives every table the full width, split by content.
- Excels extras: `model/fill.rs` is pure series logic where `offset` may be negative, so one rule covers both directions. `sheet.rs` `fill` also serves Ctrl+D and same-table paste with `series: false`, moving relative references through `formula::shift_refs`. Absolute references survive storage as a third token part (`⟦row|col|cr⟧`). A merge is stored in the table's `merges` JSON with every row and column id, like `CellRange`, and read back as indices by `live_merges`; a merged cell is always addressed by its top-left (`mergeAnchor`, `expandBox`). Filters live in the table's `filters` JSON; `hiddenRows` is derived on read and rows are kept, drawn with `visibility: collapse` so a spanning cell survives. Linked tables, charts and formulas ignore both.
- `components/sheet/` follows Numbers: tables float on a page, and column letters, row numbers and handles appear only on the selected table. A hidden `textarea` holds focus on the selection so that typing and IME start an edit. `components/chart/` uses no library: `layout.ts` turns data into marks with pure functions, drawn as React SVG or as a string for canvas previews. `components/slides/` renders one `SlideCanvas` for the editor, thumbnails and slide show. Focus must return to the stage after toolbar actions, or arrows and Delete do nothing and Esc closes the fullscreen editor.
- `markdown/` is a hand-written parser and renderer; editing happens in `components/writer/`. **Do not add a Markdown or editor library**; the owner asked for none. Keep `noteLayout.ts`, which paints Markdown on the canvas, in step with `.writer-editor[data-inline]` in `App.css`, or text jumps when entering edit mode.

## Conventions

- Code comments, test names and UI strings are in Traditional Chinese. TypeScript uses 4-space indentation.
- Destructive actions go through right-click menus and the confirm dialog (`useDeletion.tsx`), not delete buttons.
- Drag and drop uses pointer events, because Tauri intercepts HTML5 drag and drop on Windows.
- Files dropped from the OS arrive through `onDragDropEvent`. Note and image paste both go through the `paste` event, and copying a note overwrites the system clipboard so the newest copy wins.

## Verifying in the real app

The owner usually keeps `npm run tauri dev` running with real data, so port 1420 and `target/debug/code-alexa.exe` are in use. **Never stop that session, and never use `taskkill /IM code-alexa.exe`.** Running `npm install` has stopped that session both times it was tried, so warn the owner to restart it afterwards.

The browser preview has no Rust backend, so `invoke` calls fail there. To exercise the app end to end, copy the exe and `resources/drawio` (as `drawio/` next to the exe) to a scratch folder and launch the copy with:

- `ALEXA_DATA_DIR`: an isolated database. It is only honoured in debug builds.
- `WEBVIEW2_USER_DATA_FOLDER`: without this the second instance exits.
- `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<new port>`: use a fresh port per launch, because a stale WebView2 can keep holding the old one.

A release build ignores `ALEXA_DATA_DIR` and opens real data; to test production origins build with `CARGO_PROFILE_RELEASE_DEBUG_ASSERTIONS=true` and `--features tauri/custom-protocol`. Then drive it over CDP. The copy reuses the running Vite server. If `tauri dev` is not running, start Vite first.
